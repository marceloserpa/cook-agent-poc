01 / the current workflow

Working with agents locally is powerful.
Coordinating the work is the hard part.

Back and forth

Context switching

Read an output, clarify the task, approve a change, inspect again, and restart the conversation.

Parallel work

Manual coordination

Independent agents need separate workspaces, clear boundaries, and a way to compare results.

Approval timing

Human in the loop

Approvals can pause a run. Switching away and returning later adds friction and lost context.

FOMAT

Fear Of Missing Agent Time — an informal name for the feeling that idle agent time is wasted time.

The pain is coordination around the agent

02 / cook

“A simple CLI for orchestrating Claude Code, Codex, and OpenCode.”

Cook gives agent work a small workflow vocabulary: repeat, review, branch, and resolve.

Cook is the coordinator. The coding and review calls still come from the configured agent CLIs.

Source: github.com/rjcorwin/cook

04 / command line

Three commands to set up and inspect the environment.

Initialize
cook init

Creates project instructions, Cook configuration, and a sandbox Dockerfile.

Diagnose
cook doctor

Checks Docker readiness, the sandbox image, agent CLIs, and credentials.

Operate
cook shell cook shell <command>

Open an interactive sandbox shell or run a command inside it.

06 / step vocabulary

Each step has one job.

Work

Implement

Runs the task prompt and creates or changes the solution.

Review

Inspect

Looks for gaps, defects, and unmet acceptance criteria.

Gate

Decide

Returns DONE or ITERATE based on the gate criteria. This is an agent step.

Iterate

Revise

Addresses review/gate findings on the next pass. If no iterate step is configured, work runs again.

Ralph

Repeat the task

An outer loop repeats work until its gate says DONE or the configured limit is reached.

Important

Bound the run

Iteration limits stop an endless loop; they do not prove the result is correct.

Roles are workflow steps; agents/models can differ by step

08 / composing commands

A small operator vocabulary
encodes a useful control flow.

# work → review / gate loop cook "Implement dark mode" review # three sequential passes cook "Implement dark mode" x3 # race three candidates, pick the best cook "Implement dark mode" v3 "least code" # compare alternatives, then pick cook "Auth with JWT" vs "Auth with sessions" pick "best security"
  • xN runs N sequential passes.
  • review adds a bounded review/gate loop.
  • vN races N versions of one task.
  • vs compares different prompts/approaches.
  • pick / merge / compare resolve the outcomes.

Operators compose left to right. Each wraps the expression before it.

Workflow grammar as a compact CLI interface

11 / execution boundary

Agent versus Docker sandbox.

Agent · native

Run on the host

  • Uses local agent CLI and host environment.
  • Fewer Docker setup steps.
  • Host permissions and credentials need careful scoping.
Docker

Run in a container

  • Uses a Cook sandbox image.
  • Outbound network is restricted by default; allowlist hosts as needed.
  • Requires a reachable Docker daemon, image build, and portable agent credentials.

13 / learnings so far

  • Review loop makes revision and stopping criteria explicit.
Needs work
